## 0. 요약 (먼저 읽을 것)

1. **[사실] 중복 청구 위험이 실제로 있습니다.** 지금 `omni_gen.py`처럼 기본 설정으로 만들면, 서버가 503·429·408·409 오류를 돌려줄 때 SDK가 **같은 생성 요청을 스스로 최대 3번 더 보냅니다(총 4번).** Omni는 503을 돌려주고도 서버에서 완성·청구한 적이 있습니다(장부 07:25 D12 360p). 즉 최대 4배 청구 위험입니다.
2. **[사실] 공개 설정으로는 완전히 꺼지지 않습니다.** `HttpRetryOptions(attempts=0)`이나 `attempts=1`을 넣어도 생성 요청은 **1번 더** 나갑니다(SDK 내부 버그). 확실한 방법은 클라이언트를 만든 뒤 아래 한 줄로 덮어쓰는 것입니다. 모의 시험에서 POST가 1번만 나가는 것을 확인했습니다.
   `client.interactions.sdk_configuration.retry_config = RetryConfig('none', None, False)`
3. **[사실] 연결 끊김("Server disconnected")과 시간 초과는 지금 SDK 버전에서 재시도하지 않습니다.** 그래서 지난번 4K 끊김 때 중복 생성은 없었습니다. 하지만 이것은 우연한 동작이라 SDK가 바뀌면 달라질 수 있습니다. 2번처럼 확실히 꺼야 합니다.

## 2. 확인된 사실

### 2-1. 자동 재시도 (중복 청구 위험)

**코드 경로 [사실]**

- `client.interactions`는 `GeminiNextGenInteractions`를 한 번 만들어 두고 다시 씁니다 (`genai/client.py:496-502`). 이 객체는 별도 SDK를 만들고 `retry_config=_translate_retry_config(http_options)`를 넣습니다 (`genai/_gaos/google_genai.py:195-208`).
- `_translate_retry_config` (`google_genai.py:140-192`) 동작
  - 설정이 없으면 `max_retries = 2 + 1 = 3`입니다(160행). 방식은 `'attempt-count-backoff'`, 연결 오류 재시도는 True(189행)입니다.
  - `HttpRetryOptions.attempts` 값을 **"재시도 횟수"로 그대로** 씁니다. 그런데 공식 설명은 "처음 요청 포함 횟수, 0이나 1이면 재시도 없음"입니다(`genai/types.py:2657-2661`). 서로 어긋납니다.
- 클라이언트를 만들 때 `_api_client.py:915`가 `retry_args()`를 부르고, 593-594행에서 **`attempts == 0`이면 그 값을 1로 바꿔 저장합니다.** 그래서 `attempts=0`을 넣어도 interactions에는 `max_retries=1`이 됩니다(1번 더 보냄).
- `interactions.create` 안의 `retries` 변수는 인자로 받지 않고 항상 비어 있습니다 (`genai/_gaos/interactions.py:426`). 그래서 클라이언트 설정을 쓰고, 재시도 대상 코드는 `408, 409, 429, 5XX`입니다(494-507행).
  - `create(retries=...)`처럼 모르는 인자를 넣으면 TypeError가 납니다 (`google_genai.py:1473-1480`). **호출마다 재시도를 끄는 인자는 없습니다.**
- 전략이 `'none'`이면 요청을 한 번만 보냅니다 (`genai/_gaos/utils/retries.py:227-285`, 285행 `return func(0)`).
- 연결 오류가 재시도되지 않는 이유
  1. 요청 중 오류가 나면 after_error 훅이 오류를 바꿔치기합니다 (`genai/_gaos/basesdk.py:271-275`).
  2. 그 훅인 `CompatErrorHook`(`_gaos/_hooks/sdkhooks.py:49`, `_gaos/lib/compat_errors.py:344-355`)이 httpx 오류를 `APIConnectionError`로 바꿉니다.
  3. 그래서 `retries.py:255-261`의 연결 오류 판별이 거짓이 되고, 바로 실패합니다.
  - 의도된 설계로 보이지 않으므로 기대지 말아야 합니다.
- `files.upload/download`(구형 경로)는 retry_options가 없으면 1번만 보냅니다 (`_api_client.py:581-592`, `stop_after_attempt(1)`). 업로드 조각 반복(`_api_client.py:2014-2027`)은 업로드 상태 머리글이 없을 때만 돌고, 업로드는 무료입니다.
- **보안 주의 [사실]:** 환경변수 `GOOGLE_GENAI_DEBUG`를 켜면 요청 머리글이 로그에 찍힙니다(`_gaos/utils/logger.py:40-44`, `basesdk.py:259-265`). 이 머리글에는 API 키가 들어 있습니다. 절대 켜지 마십시오.

**로컬 모의 시험 [사실]**

- 가짜 키를 쓰고, GEMINI_API_KEY와 GOOGLE_API_KEY는 환경에서 뺐습니다.
- `httpx.MockTransport`로 네트워크 없이 오류를 흉내 내고 POST 횟수를 셌습니다.
- 시험 코드는 부록 A에 있습니다. 실행본은 이 작업의 임시 폴더에만 있습니다.

| 설정 | 연결 실패 | 끊김(RemoteProtocolError) | 시간 초과 | 503 | 400 | get 503 | files.download 503 |
|---|---|---|---|---|---|---|---|
| 기본(지금 omni_gen.py) | 1회 | 1회 | 1회 | **4회** | 1회 | 4회 | 1회 |
| `HttpRetryOptions(attempts=0)` | 1회 | 1회 | 1회 | **2회** | 1회 | 2회 | 1회 |
| `HttpRetryOptions(attempts=1)` | 1회 | 1회 | 1회 | **2회** | 1회 | 2회 | 1회 |
| `retry_config = RetryConfig('none', None, False)` 직접 덮어쓰기 | 1회 | 1회 | 1회 | **1회** | – | 1회 | – |

- stream=True로 503을 받아도 처음 POST는 똑같이 4회 나갑니다(기본 설정).
- 직접 덮어쓰면 같은 객체의 `get`도 재시도하지 않습니다. 그래서 상태 확인(get)은 **재시도해도 안전한 별도 클라이언트**로 하거나, 직접 반복문을 쓰는 것이 좋습니다.

### 2-3. 옵션 정리

| 옵션 | 하는 일 | 이 프로젝트에서 |
|---|---|---|
| `background` | 서버에서 돌리고 바로 id를 돌려줍니다. `get(id)`로 확인합니다 [사실]. `store=False`이면 쓸 수 없습니다(공식 문서) | 연장에 쓰면 400. **첫 클립까지 background로 만든 줄기는 시험 안 함** |
| `stream` | 이벤트 순서: created → step.start/delta/stop → completed (공식 문서) | 4K에서 이벤트가 끝에 몰려 옴. 다음 연장 불가 |
| `store` | 기본 True. 유료 등급은 55일 보관. False이면 연장(previous_interaction_id)과 background가 불가 (공식 문서) | True 유지 |
| `response_format.delivery` | `'inline'`(응답 본문에 base64 영상) 또는 `'uri'`(파일로 받음) (`videoresponseformat.py:40-47`). `gcs_uri`는 Vertex 전용 | 4K 16초가 134~262MB라 inline은 비현실적. **uri 유지** |
| `response_format.duration` | 문자열 `'3s'`~`'10s'` (공식 스크립트가 3~10 정수 검사) | 지금은 8초만 씀 → **4~6초도 쓸 수 있음** |

### A. background 연쇄 — 시험이 성공하면 1순위

**방법**
- 첫 클립부터 모든 단계를 `background=True`로 보냅니다.
- 그러면 id를 바로 받고, 짧은 `get(id)` 요청으로 1분마다 확인합니다.
- 긴 요청이 하나도 없으니 300초 문제가 사라집니다. 한 줄기를 40초까지(8초 + 4초×8, 또는 8초×5) 이을 수 있습니다.

**최소 유료 시험 (360p, 4초짜리)**

| 순서 | 내용 | 비용 | 알게 되는 것 |
|---|---|---|---|
| T1 | 360p 첫 클립 4초, background=True, 첫 프레임 1장 | 약 $0.14 | background 결과가 completed가 되고 output_video를 내려받을 수 있는지 |
| T2 | T1에서 360p 4초 연장, background=True | 400이면 $0(이전 400 건은 청구 흔적 없음), 되면 약 $0.16 | **핵심:** background로 이어지는가 |
| T3 | T2에서 다시 4초 연장, background=True | 약 $0.16 | 3단 이상, 줄기 전체 파일이 돌아오는지 |
| (T2′) | T2가 400이면, T1에서 **일반** 4초 연장 | 약 $0.16 | background로 만든 첫 클립이 일반 연장 재료가 되는지(선택) |

- 합계 최대 약 $0.46~0.62입니다.
- 성공하면 4K에서는 첫 8초부터 background로 갑니다.

**실패 시**
- 400은 바로 오고 청구되지 않는 것으로 보입니다. 그 경우 B로 갑니다.

**복구**
- id가 있으므로 `get(id)`로 결과를 받습니다.
- `get` 자체가 실패하면 그냥 다시 물어보면 됩니다(GET은 생성이 아님).

### B. 짧은 연장 단계 + 시간 재며 계속 — 기본안

**방법**
- 1단계 재제작(이번에 어차피 만듦)을 **4K 첫 8초(150~190초, 일반 요청) + 4초 연장 × 2**로 만듭니다. 16초 비용은 $5.02로 8+8초($4.95)와 거의 같습니다.
- 단계마다 요청 시간을 기록합니다.
- 다음 단계 예상 시간(직전 단계 × 1.2)이 **240초 이하**이면 같은 줄기를 계속 잇습니다. 1단계 → 2단계 사이에도 이음새 재시작이 없습니다.
- 넘으면 그 줄기는 거기서 끝내고 겹침 재시작(아래)을 합니다.

**최소 유료 시험**
- 별도 시험은 없습니다. 1단계 재제작의 첫 4초 연장 1회(약 $1.29)가 곧 시험입니다.
- 4초 연장이 240초를 넘으면 4초 단계로도 3단은 어렵다는 뜻이므로 C로 바꿉니다.

**실패(끊김) 시**
- 서버에서 완성되므로 아래 5장의 절차로 `files.list()`에서 영상을 되찾습니다(청구는 됨).
- 그 영상이 줄기의 마지막이 되고, 겹침 재시작으로 넘어갑니다. 돈은 버리지 않고 이음새가 하나 늘 뿐입니다.

**장점**
- id가 살아 있는 동안 어떤 단계가 나쁘게 나오면(장면 끊김, 팝), **그 단계만 바로 앞 id에서 다시** 만들 수 있습니다($1.29).
- 이 프로젝트는 이미 D12와 D12b를 같은 D1에서 만들어 본 적이 있습니다.

### C. 2단 줄기(8+8초) + 겹침 재시작 — 최후의 기본

- 지금까지의 방식 그대로입니다. 연장이 끊겨도 영상은 되찾으니 결과는 같고, 줄기가 16초에서 끝납니다.
- 90초에 재시작 이음새가 약 5번 생기는 것이 단점입니다.

### 겹침 재시작 절차 (B·C 공통)

1. 앞 줄기 A의 4K 원본에서 끝보다 k초 앞(k = 약 1초)의 프레임을 PNG로 뽑습니다(`next_chain_frame.py --at -1.0`). 이 프레임에는 손대지 않습니다. 정리·실사화·색 보정을 하면 이음새에서 장면이 튑니다(`장면계획.md` 2장 3번). 새 줄기의 첫 생성은 9초로 만듭니다(겹침·느린 출발로 1.7~2.9초가 잘려 나감, `장면계획.md` 5장).
2. 새 줄기 B의 첫 클립을 만듭니다.
   - FIRST_FRAME에는 그 프레임을 넣습니다.
   - 프롬프트에 "camera is already moving at a constant speed, continuing the same direction and turn"을 넣습니다.
   - 필요하면 타워 참조 이미지도 넣습니다. 360p로 먼저 확인합니다.
3. A의 끝 부분 k초와 B의 앞 부분을 `align_to.py`로 비교합니다. 위치·크기·속도가 가장 잘 맞는 프레임 짝에서 **자르기만** 하고, 크로스페이드는 쓰지 않습니다.
4. `pop_detect.py`, `clip_check.py`로 이음새의 팝, 속도 변화, 디졸브를 잽니다.
   - 첫 프레임을 다시 그려서 생기는 세부 차이가 팝으로 보이면, 자르는 지점을 B의 0.5~1초 뒤(움직임이 붙은 뒤)로 옮깁니다.

**쓰지 말 것**
- 업로드 연장으로 다시 시작하기: 입력을 다시 그려 PSNR 약 14dB이고 4~6프레임이 밀리므로 붙일 수 없습니다.
- 광류로 속도 맞추기: 잔상이 생깁니다.

## 5. 유료 호출 안전 절차 (일요일 체크리스트)

**요청 전**

1. 유료 생성은 **한 번에 하나만** 보냅니다. 동시에 여러 개 보내면 되찾을 때 어느 것인지 헷갈립니다.
2. 재시도는 끕니다(2-1의 `paid_client()`). 시작할 때 `assert`로 `strategy == 'none'`을 확인합니다.
3. `GOOGLE_GENAI_DEBUG`가 꺼져 있는지 확인합니다. 키 값은 절대 출력하지 않습니다.
4. 시작 시각(UTC)을 기록하고, `files.list()`로 지금 있는 파일 이름 목록을 저장해 둡니다(무료).
5. 장부에 먼저 **`pending` 행을 예상 비용으로** 적고, 상한 계산에 넣습니다.
   - (반영됨) `gen_api.spent()`는 `ok`와 미확정(`pending`·`unresolved`, 예상액)을 모두 더합니다. 적기 직전에 장부 잠금 안에서 상한·80% 보고선을 한 번 더 봅니다.
   - 상한: 장부 누적 $121.98, 80% 보고선 $108.98(`work/final/budget.json`, 스크립트가 자동으로 읽음).

**요청 중 오류가 나면 (400 즉시 거절 제외)**

6. **절대 바로 다시 보내지 않습니다.** 끊김, 503, 시간 초과 모두 해당합니다.
7. `files.list()`에서 새 영상을 찾습니다(`omni_gen.py`가 스스로 함: 기본 20초마다 6분. 그 뒤에도 `--recover-only`로 몇 번이고 다시 확인할 수 있음, 무료).
   - 조건: `source == GENERATED`, `mime_type`이 video, `create_time > 시작 시각`, 4번 목록에 없던 이름.
   - 후보가 딱 하나이고 다른 미확정 요청이 없을 때만 바로 내려받습니다(`files.download(file=...)`). 후보가 여럿이면 고르지 않고 json에 적은 뒤 사람이 `--recover-file`로 고릅니다.
   - `ffprobe` 길이로 어느 요청의 결과인지 확인합니다. 연장이면 줄기 전체 길이가 나옵니다.
8. 찾으면 `pending`을 `ok`(되찾음, 예상액)로 바꿉니다. 못 찾으면 **`unresolved`(청구 여부 모름, 예상액 그대로 상한·80% 계산에 남김)**로 바꿉니다. 0달러로 보지 않습니다.
   - 지금까지 끊김·503 4건이 모두 서버에서 완성·청구됐기 때문입니다.
   - 다시 시도는 사람이 Google 결제 화면에서 청구가 없었음을 확인하고 `--mark-not-billed <표식> --reason "확인 내용"`으로 0달러 처리한 뒤에만 합니다(또는 다른 `--out` 이름으로, 앞 행은 상한에 남긴 채).
9. 503 뒤에는 여러 개가 생겼는지도 봅니다. 기본 설정으로 돌렸다면 최대 4개가 생길 수 있었습니다.
10. 끊긴 직후 `curl -sS "$HTTPS_PROXY/__agentproxy/status"`(로컬)를 확인하고 결과를 기록합니다. 3장 1번 추정을 확인하는 용도입니다.

**background를 쓸 때**

11. 생성 요청은 `paid_client()`로 보냅니다. 확인(`get`)은 `poll_client()`로 1분마다 하고, `status`가 `completed / failed / cancelled / incomplete`가 될 때까지 기다립니다.
12. 상태가 `in_progress`로 30분 넘게 멈춰 있으면 사용자에게 알리고 기다립니다. 함부로 cancel하지 않습니다. 이미 청구됐을 수 있습니다.
    - (반영됨) `omni_gen.py`는 `in_progress`·`queued`·`requires_action`이면 `--poll-wait`(기본 30분) 동안 get으로 기다리고, 그래도 안 끝나면 `unresolved`로 두고 종료 코드 20으로 끝냅니다. `failed`·`cancelled`는 응답 토큰에 영상 출력이 없을 때만 0달러로 봅니다.

**줄기 관리**

13. 단계마다 id, 걸린 시간, 줄기 길이, 출력·입력 토큰을 json에 남깁니다.
14. 다음 단계에는 늘 **가장 최근에 성공한 단계의 id**를 씁니다. 편집에는 그 단계의 **줄기 전체 파일**을 씁니다.
15. 한 줄기는 같은 날 끝냅니다(파일이 48시간 뒤 지워질 수 있다는 추정).

## 부록 A. 재시도 횟수 모의 시험 (네트워크 없음)

실행 방법: 키 환경변수를 빼고 실행합니다.

`env -u GEMINI_API_KEY -u GOOGLE_API_KEY -u GOOGLE_GENAI_DEBUG HTTPS_PROXY= python3 -I 이_파일.py`

```python
"""네트워크 없이 SDK 재시도 횟수를 세는 시험. 가짜 키, MockTransport만 사용."""
import os, httpx
assert 'GEMINI_API_KEY' not in os.environ and 'GOOGLE_API_KEY' not in os.environ
from google import genai
from google.genai import types
from google.genai._gaos.utils import RetryConfig

calls, MODE = [], {'m': None}

def handler(req):
    calls.append(req.method)
    m = MODE['m']
    if m == 'disconnect':
        raise httpx.RemoteProtocolError('Server disconnected without sending a response.', request=req)
    if m == 'connect':
        raise httpx.ConnectError('mock', request=req)
    return httpx.Response(503, json={'error': {'code': 503, 'message': 'mock', 'status': 'UNAVAILABLE'}})

def make(retry_options=None, none=False):
    kw = dict(base_url='http://127.0.0.1:9/', timeout=60_000,
              httpx_client=httpx.Client(transport=httpx.MockTransport(handler)))
    if retry_options is not None:
        kw['retry_options'] = retry_options
    c = genai.Client(api_key='FAKE-KEY', http_options=types.HttpOptions(**kw))
    if none:
        c.interactions.sdk_configuration.retry_config = RetryConfig('none', None, False)
    return c

def posts(c, mode):
    MODE['m'] = mode; calls.clear()
    try:
        c.interactions.create(model='gemini-omni-1.1-flash', input=[{'type': 'text', 'text': 'x'}],
                              response_format={'type': 'video', 'delivery': 'uri', 'aspect_ratio': '16:9',
                                               'duration': '4s', 'resolution': '360p'}, store=True)
    except Exception:
        pass
    return calls.count('POST')

for label, c in [('기본', make()), ('attempts=0', make(types.HttpRetryOptions(attempts=0))),
                 ('attempts=1', make(types.HttpRetryOptions(attempts=1))), ("RetryConfig('none')", make(none=True))]:
    print(label, '| 503:', posts(c, '503'), '| 끊김:', posts(c, 'disconnect'), '| 연결실패:', posts(c, 'connect'))
# 2026-10-16 결과: 기본 4/1/1, attempts=0 2/1/1, attempts=1 2/1/1, none 1/1/1
```
