# 화질 분석 — 생성 영상이 원본 이미지 화질에 못 미치는 이유와 대책

- 측정 스크립트: `work/scripts/quality_check.py`
- 결과: `work/test1/quality/`(수치 표, 확대 비교 이미지)
- 고친 점(2026-10-13): 처음 측정은 원본을 1920 크기로 키워서 비교해 원본이 불리했습니다. 지금은 모든 대상을 1280×720으로 줄여서 비교합니다(검증 단계에서 지적받아 수정).

## 2. 원인

1. **Veo 1080p는 입력의 잔무늬를 증폭하고, 연쇄하면 쌓입니다.** (측정과 눈으로 모두 확인)
   - 깨끗한 원본에서 시작해도 8초 동안 잔무늬가 2배 넘게 늘었습니다(T1: 7.6 → 16.4%).
   - 그 마지막 프레임으로 다음 클립을 만들면 처음부터 30% 수준이 됩니다. 나무, 구름, 산 능선, 건물에 흰 테두리가 생깁니다.
   - 입력을 720p로 줄여 정리해도 거의 줄지 않았습니다(시험 1). 입력의 테두리 자체보다, 입력에 이미 있는 잔무늬를 모델이 다시 키우는 것이 핵심으로 보입니다.
2. **영상 모델의 구조적 한계** (공개 논문·기술 보고서 기준)
   - Veo 3는 압축된 잠재 공간에서 영상을 만들고 디코더로 복원합니다(Veo 3 기술 보고서).
   - 시작 이미지조차 그대로 복사되지 않고 다시 그려집니다.
   - 비슷한 구조의 공개 모델들은 공간을 8배(또는 그 이상) 압축합니다. 미세한 질감과 큰 움직임이 함께 있으면 세부 손실이 가장 커진다고 밝힙니다(Meta Movie Gen, Wan, HunyuanVideo, LTX-Video).
3. **1080p·4K 생성 방식**
   - 구글은 2026년 1월 발표에서 1080p·4K를 업스케일링이라고 소개했습니다.
   - Gemini API 문서는 "직접 생성"이라고 적고 있어 표현이 엇갈립니다.
   - 내부 기본 해상도는 공개되지 않아 확인하지 못했습니다.
4. **압축**
   - Veo 원본 파일 자체의 압축 손실은 따로 측정하지 못했습니다. Gemini API에서는 무손실에 가까운 출력 옵션을 쓸 수 없습니다(Vertex 전용).
   - 대화창으로 보낸 압축본은 손실이 눈에 보일 수 있습니다.

## 3. 대책 비교

| 방법 | 결과 | 클립당 비용(8초) | 판정 |
|---|---|---|---|
| 1080p 그대로 연쇄 | 뒤로 갈수록 흰 테두리가 심해짐 | $0.96 | 불가 |
| 입력만 720p로 정리 | 거의 개선되지 않음 | $0.96 | 효과 없음 |
| **4K 생성 → 1080p로 축소** | 흰 테두리가 크게 줄고 구름·능선·건물이 자연스러움(눈 확인). 장면 연속성 정상, 디졸브 없음 | $2.40 | **권장** |
| 720p 생성 → 로컬 확대(lanczos + CAS, 16초당 약 1.5분) | 테두리는 없지만 흐림 | $0.80 | 화질 낮음 |
| 720p 생성 → Real-ESRGAN 확대(이 환경 CPU) | 16초당 40분~1.7시간. 그림처럼 다시 칠해져 원본 느낌이 바뀜(조사 단계 시험) | $0.80 | 비권장 |
| 고급 모델(Standard) | 같은 입력에서 Fast와 화질 차이 없음 | $3.20 | 화질 목적으로는 불필요 |
| 후처리(축소·확대, 양방향 필터, 잡음 제거) | 테두리가 조금만 줄어듦 | 0 | 보조 수단 |

참고로 4K도 8초 클립만 가능하고, 연장 기능은 쓸 수 없습니다(연장은 720p 전용).

## 4. 남은 확인 사항

- 4K 방식을 전체 연쇄에 적용했을 때 몇 번째 클립까지 깨끗하게 유지되는지 확인하지 못했습니다. 이번 시험은 두 번째 클립까지입니다.
- 정상 속도 재생에서 잔무늬가 프레임마다 바뀌어 보이는지 확인하지 못했습니다. 직접 재생 확인이 필요합니다.
